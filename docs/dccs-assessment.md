# DCCS 試玩與正式評測重構

本次直接修改既有 `/test-dccs`。登入、STEP 影片、森林背景、服飾與木箱圖片、評測 Session、統一結果儲存及結果路由沿用現有機制，沒有新增套件。

依介面精簡需求，遊戲畫面移除規則／階段標題、試玩進度、對話文字泡泡、`voice.webp` 重播按鈕、「大人協助（長按）」入口與長按事件，以及「準備好開始挑戰了！」整個提示框。正常畫面保留小雞旁白、衣服、木箱與操作動畫；語音仍自動播放。刺激物與木箱使用以下 1360 × 989 固定相對座標；依最新補充需求，小雞在沒有中央物件時放大置中，僅有中央衣服／帽子時使用左上角的小尺寸。

## 狀態流程

```text
start → video_step
  → practice_intro → practice_question → practice_feedback
                        ↑                   │
                        └── 尚未連續答對 2 題 ┘
  → practice_passed → formal_intro → formal_question → formal_transition
                                        ↑                 │
                                        └── 本階段還有題目 ┘
  → 下一規則 practice_intro，或最後一階段 completed
```

規則依序為 `color`、`category`、`bag_color`。正式逐題紀錄另保留原有 `color_test`、`type_test`、`bag_color_test` phase，供舊評分與分析使用。

每規則的試玩計數獨立。正確累加、錯誤歸零，連續正確兩題才通過；語音失敗不會繞過門檻。種類試玩優先使用紅色上衣與藍色帽子，與木箱實際顯示的「左藍色上衣／右紅色帽子」形成衝突，避免沿用顏色規則也能連續答對。練習題庫獨立建立，沒有消耗或改寫正式題庫。

## 動畫與互動

- 刺激物淡入並由 0.95 倍恢復原尺寸，預設 300 ms。
- 三種規則的試玩開放作答時，只在正確答案的分類箱旁顯示一個 `mouse.webp` 點擊手勢，放在木箱右側，避開箱內分類圖示。依既有 `getDccsCorrectPosition` 與題目 metadata 選擇提示位置，手指不攔截點擊。介紹、載入、回饋及正式評測不顯示，第一次有效點擊立即收起，下一題可作答時再出現。系統「減少動態效果」模式保留靜態手指。
- 第一次有效點擊立即鎖定兩箱、寫入紀錄，再按實際元素位置將物件投入所選木箱；投入動畫 450 ms，木箱短暫縮為 0.98 倍。
- 正式模式不把正誤狀態傳入畫面；兩種結果一律使用相同投入動畫及原有 600 ms 換題間隔，沒有星光、搖晃、正誤色彩、得分或連續答對數。
- 試玩正確保留小雞與語音回饋，籃子上方的三顆星星已依後續需求移除；錯誤只重述規則，不指出答案。動畫完成後等待回饋語音結束，且至少保留 1000 ms 回饋時間。
- 旁白使用 `chicken.webp`（張嘴）與 `chicken01.webp`（閉嘴），保留 `idle`、`speaking`、`happy`、`encourage`、`transition` 五種溫和動作。實際播放語音時以 560 ms 週期交替嘴型，暫停、等待載入及播完後閉嘴；系統「減少動態效果」模式使用靜態嘴型。
- 一般與裝袋圖片皆使用最新指定的 30% 寬度容器，保持各自的原始圖片比例，不再套用舊版裝袋圖的額外 1.18 倍放大。只有試玩介紹保留既有一次 1.08 倍提示；正式題不做提示性放大，也不修改圖片透明度與顏色。
- 不提供長按協助入口或跳過未通過試玩直接進入正式題的選項。離開頁面仍由既有 recorder 保存中斷紀錄。

小雞在旁白播放時出現，包括正式開始語音；中央有衣服／帽子時使用左上方 13% 寬度，沒有物件時以 72% 寬度置中，只有下方兩個分類箱時以 54% 寬度放在上方中央，避開箱子。兩張嘴型圖共用相同位置及尺寸，不會因切換嘴型推動其他圖示。正式作答時保留原有退出旁白畫面的行為，並停用角色循環動畫。窄螢幕維持相同情境座標。

`mouse.webp` 用於試玩分類箱的點擊引導，並保留原開始／影片／結果頁的手指提示；旁白角色仍使用小雞。

## RT 與資料保存

RT 起點在刺激物及兩箱圖片完成載入、300 ms 出現動畫結束並經過兩次 `requestAnimationFrame` 後，與開放作答同步以 `performance.now()` 記入 ref。終點為第一次有效點擊；投入、回饋及換題時間不納入 RT，系統時鐘變動不影響數值。一般 rerender 與語音播放狀態不會重新開始正式計時。

正式資料只寫入原有 `trials`／`trialLogs`／`records`，並保留舊欄位。相容新增 `mode: formal`、`session_id`、`task`、`rule_type`、`trial_index`、`stimulus_id`、`left_target_id`、`right_target_id`、`correct_target`、`selected_target`、`is_correct`、`reaction_time_ms`、`is_switch_trial`、`error_type`、`presented_at`、`responded_at`。

`session_id` 取既有 recorder 建立的 behavioral Session ID；結果仍以原有 result ID 交給 `useTestAttempt.complete`。新增的左右 target ID 指向實際箱圖中的 `blue_shirt` 與 `red_hat`；舊 `topTargetSampleCardId` 等邏輯題庫欄位保留。新 `error_type` 依實際箱圖推論前規則錯誤，並記錄 `error_type_basis: displayed_box_references` 與 `previous_rule_target`；舊 `errorType`／`isPerseverativeError` 繼續供現有計分使用，沒有暗中改變舊計分依據。

試玩只保存在獨立 `practiceLogs` 與 `practiceSummary`，含規則、題次、正誤、連續答對數、累計嘗試次數、通過狀態與語音重試次數，並相容保留回合欄位。沒有把試玩 RT、錯誤或題數加入正式評分。每次作答同步 checkpoint，未通過就離開的施測也保留其理解狀態。

**不需資料庫 migration。** 既有結果 `payload`／`rawResult` JSON 結構可保存新增資料；沿用 outbox 及既有 Session／trial ID 防重複機制。資料庫雲端連線未於本次實際寫入驗證。

重新整理／返回頁面不會自動重送或續做舊正式題。原 recorder 將舊施測標記中斷，重新開始建立新施測；BFCache 還原也回到開始畫面。卸載／離開會取消語音與動畫回呼，完成使用 ref 保證只提交一次。

## 需要研究者確認的項目

1. 新指示語的正式錄音稿；目前使用既有語音映射，旁白角色已依後續需求改為小雞。
2. 出現 300 ms、投入 450 ms、試玩回饋至少 1000 ms、通過至少 1200 ms 為可調整介面設定，並非新訂研究規格；正式換題沿用 600 ms。
