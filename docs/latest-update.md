## 1. 專案概要

執行功能森林遊戲是一套兒童認知遊戲、行為紀錄與研究分析平台，提供四種使用情境：

| 使用情境 | 主要內容 |
| --- | --- |
| 兒童端 | 六款正式測驗、操作教學與試玩、日常訓練、結果與遊戲獎勵 |
| 家長端 | 兒童資料、歷史結果、訓練安排、結果說明與小助手 |
| 醫療端 | 授權個案清單、結果趨勢、逐題紀錄、報告匯出與 RAG 助手 |
| 研究端 | 資料品質、特徵工程、統計、行為預測、模型解釋、推薦策略與縱向追蹤 |

主要技術為 React 18、React Router、Recharts、Node.js／Express、Supabase PostgreSQL／Auth，以及模型 API 與向量檢索。ExcelJS、docx 等套件提供報告輸出。

資料流程為：**遊戲操作 → 逐題紀錄 → 任務計分與分析 → 本機保存／雲端同步 → 家長、醫療與研究介面 → 下一次訓練安排。**

## 2. 六款遊戲與目前正式測驗規則

現行任務為 SRT、PM、CBT、ARI、DCCS、LB；ARI 已取代 SSG。研究入口依現行六項任務篩選，歷史原始紀錄保留。

以下參數以目前 `src/utils/*Protocol.js` 與實際測驗頁面核對；部分既有文件仍留有較早版本描述。

| 遊戲 | 核心操作與觀察方向 | 目前正式測驗 |
| --- | --- | --- |
| SRT 松鼠採橡實 | 點擊好橡實、忽略壞橡實；觀察持續注意、漏接、誤點與反應波動 | 固定 8 分鐘；刺激起始間隔隨機 1 或 3 秒，每顆顯示 500 ms。每組 4 顆為 3 顆好橡實、1 顆壞橡實，組內隨機排列 |
| PM 圖片記憶 | 記住圖片並從選項找回；觀察記憶負荷與選取過程 | 記憶物件數 1～7，每個數量 2 題；觀看 5 秒、作答上限 15 秒。同跨度兩題皆失敗時停止 |
| CBT 石頭小橋 | 依亮燈順序點擊石頭；觀察視空間序列記憶 | 全程固定 9 顆石頭及位置；序列由 2 步增加至最多 7 步，每個長度 2 題。每顆亮 0.8 秒、間隔 0.26 秒，作答上限 15 秒，保留失敗／逾時停止規則 |
| ARI 貓狗合唱團 | 聽到貓叫選狗、狗叫選貓；觀察聽覺辨識與反向反應 | 20 題，平衡聲音與正確左右位置；作答上限 5 秒，不提供重播 |
| DCCS 服飾分類 | 依顏色、種類及後續顏色規則分類；觀察規則切換 | 素材足夠時為 2 題練習，加上 6 題顏色、8 題種類、6 題裝袋顏色正式題；目前沒有自動作答逾時計時器 |
| LB 門牌導航 | 依數字及顏色交替路線點選；觀察順序追蹤與規則維持 | 兩段路線：1～10 正序，以及紅 1、藍 2……藍 10；不套用訓練的倒序、提示或限時 |

### 正式測驗前的試玩

- **SRT**：完成操作示範與刺激練習；需連續答對兩題，且曾正確點擊好橡實、正確忽略壞橡實。
- **ARI**：連續兩題正確才通過；錯誤會重設該組星星，最多三組未通過後顯示協助。重播與技術播放失敗不計入輪數。
- **LB**：先完成黃色 1～5 正序，再完成黃／藍交替至 6 的兩段試玩。

這些試玩不納入正式測驗成績；正式流程開始後才建立對應正式紀錄。

## 3. 最新訓練設計

SRT、PM、CBT、ARI、LB 統一提供入門、簡單、中等、難、專業五級；DCCS 保留十個配置級。地圖關卡順序、遊戲難度與題次分別記錄，分析時需核對實際設定。

| 遊戲 | 目前訓練重點 |
| --- | --- |
| SRT | 入門等待點擊後才換題，等待 3 秒提供提示；簡單固定每秒普通橡實；中等加入壞橡實與獎勵橡實；難與專業使用 1～3 秒變動間隔，專業顯示時間為 0.8 秒 |
| PM | 五級記憶負荷依序為 2、3～4、4～5、5～6、6～7 個物件；作答均為 15 秒，觀看依物件數為 3 或 5 秒。入門未開始點選滿 3 秒才提示；單次訓練不因反應速度變更級別 |
| CBT | 五級分別使用 5～9 顆石頭、2～3 至 6～7 步序列；入門與簡單位置固定，中等以上每題變動位置並於觀察階段呈現環境動畫。所有級別依原順序作答 |
| ARI | 每場 12 題，依級別調整作答上限、重播、提示與背景干擾；詳見下表 |
| LB | 入門數字正序、簡單與中等正序顏色交替、難為數字倒序、專業為倒序顏色交替；每場 10 個目標。入門每步 20 秒，其餘 15 秒；入門／簡單提供規定提示 |
| DCCS | 十個配置級調整規則、題目與干擾條件；實際提示執行須以頁面及 trial 核對，不能只依配置文字推定 |

### ARI 五級設定（協定 3.0.0）

| 難度 | 每題作答上限 | 重播 | 提示 | 背景干擾 |
| --- | --- | --- | --- | --- |
| 入門 | 10 秒 | 可 | 等待 3 秒或連續錯誤達門檻時提供提示 | 無 |
| 簡單 | 10 秒 | 可 | 無 | 無 |
| 中等 | 5 秒 | 不可 | 無 | 無 |
| 難 | 5 秒 | 不可 | 無 | 有 |
| 專業 | 3 秒 | 不可 | 無 | 有 |

來源：[ARI 協定](../src/utils/ariProtocol.js)、[訓練頁](../src/pages/TrainingPage_ARI.jsx)。

### 計分、難度與推薦的分工

任務計分器產生表現摘要；規則式分析器提供同一遊戲的下一次難度或支持建議；線上 UCB1 用於選擇接下來的訓練遊戲。RAG 助手負責解釋個案紀錄及相關來源。這些輸出各自有不同用途。

PM 主分數以正確率、記憶負荷與作答過程為主，反應速度及時間變異權重為 0；反應較慢不能單獨成為降級依據。各遊戲保留提示事件，分析時可區分獨立與有提示作答。

## 4. 資料保存與醫療端

六款正式測驗共用測驗保存流程：開始、逐題作答及中斷時保留快照，完成與中斷沿用同一組結果與 trial 識別資料。結果可先保存本機，再依登入、權限及連線狀態同步。

資料包含任務、模式、難度、協定版本、完成狀態、題目設定、預期與實際反應、正確與否、反應時間、提示、點擊歷程及錯誤類型。PM 新增可能混淆的錯選關聯；CBT 保留提前點擊及等待／答案提示；SRT 保留反應波動與實際刺激間隔；LB 保留逐步提示原因與時間。

醫療端可查看個案趨勢、篩選歷史紀錄、檢視單題資料與刺激欄位，並匯出 Excel。舊紀錄缺少新增欄位時顯示「未記錄」。未完成題的事件可保留，計算已完成題的正確率及記憶摘要時需依各任務規則處理。

研究資料採 Participant → Session → Task Session → Trial 階層。原始 trial、清理與衍生資料分開，保留品質標記、排除理由及版本資訊。

| 分頁 | 內容 |

畫面使用本機穩定的 `P-001` 等參與者代號；跨裝置核對與匯出仍以研究 UUID 為準。既有模型保留至少 20 位參與者等資料條件，資料不足、模擬預覽與執行錯誤各自呈現。

## 6. AI／RAG 與新增評估套件

醫療端助手結合已清理的個案資料、系統計算指標與知識庫段落產生回答。家長結果頁的小助手目前使用本機規則式回覆；新增寄信功能並未改變其回答來源。

### 本次工作區新增內容

- 提供 **50 個固定合成情境**，涵蓋六款遊戲、結果比較、缺值、來源引用、檢索降級、診斷與用藥界線，以及提示注入。
- 抽出可注入測試依賴的正式助手 handler，評估沿用資料清理、文件篩選與提示組裝。HTTP 請求無法指定測試依賴。
- 模型客戶端改為需要時才初始化，支援無金鑰離線評估。
- 數值清理保留缺值，避免把 `null`、未提供或空白內容誤轉成 0；實際數值 0 仍保留。
- 輸出 JSON 與 UTF-8 BOM CSV，每完成一題更新報告，保留完整度、回答、自動檢查與人工審查欄位。

| 評估模式 | 使用資料與回答 | 可確認範圍 |
| --- | --- | --- |
| `offline` | 合成段落與回覆替身，不連外 | 輸入驗證、資料清理、提示組裝、來源處理與故障降級 |
| `model` | 合成段落與真實模型回答 | 上述流程及回答初步檢查；會產生模型 API 費用，仍需人工核對 |

兩種模式均未評估真實 Supabase 向量檢索品質，也未涵蓋完整 HTTP 驗證、權限及速率限制。離線通過數不能作為真實回答正確率；合成段落不能作為文獻證據。

詳細情境與報告判讀見 [RAG 評估說明](rag-evaluation.md)。

## 7. 新增小助手問答寄信

家長結果頁與醫療 Dashboard 均加入「本次問答自動寄至註冊信箱」選項。

- 每次詢問預設不寄送；勾選後僅寄送本次問題與完成的回答，下次詢問重新選擇。
- 收件地址由後端驗證登入帳號後取得，不使用前端指定的收件人。
- 信件包含詢問時間、問題、回答、可用來源及備援標記；時間以臺灣時區呈現。
- 畫面顯示未寄送、交寄中、服務已接受或失敗；失敗可重試且不影響聊天室回答。
- 重試沿用問答紀錄 ID 與使用者範圍的冪等鍵；「已交寄」表示供應商接受請求，實際收件仍需確認。
- 登出、切換帳號或切換個案時重設寄送選擇與相關重試紀錄。

API 為 `POST /api/assistant-email`，透過 Supabase 登入驗證與角色限制；預設速率上限為每分鐘 10 次。寄送使用 Resend，需設定後端環境變數：

| 變數 | 用途 |
| --- | --- |
| `RESEND_API_KEY` | 寄信服務金鑰 |
| `ASSISTANT_EMAIL_FROM` | 供應商已驗證網域的寄件地址 |
| `ASSISTANT_EMAIL_RATE_MAX` | 每分鐘寄送 API 請求上限，預設 10 |

範例位於 [`.env.rag.example`](../.env.rag.example)。這些設定只供後端使用，不加入 `REACT_APP_` 前綴。未設定寄信服務時 API 回報未啟用。

目前問答與重試資料保留於頁面記憶體，沒有另外建立長期寄送佇列。完整設定與驗收流程見 [問答寄信說明](assistant-email.md)。

## 8. 成就與開發測試入口

### 新版成長徽章

依系統推薦或醫療指定難度，完整完成一次訓練且正確率至少 80%，累積一次達標紀錄。每位兒童、每款遊戲、每個臺灣日曆日最多一次。

| 等級 | 累積達標次數 |
| --- | ---: |
| 銅級 | 1 |
| 銀級 | 3 |
| 金級 | 6 |
| 鑽石級 | 10 |
| 星耀級 | 15 |

正式測驗、遊戲測試模式、未完成場次及手動選擇未被推薦的難度不累積。已獲徽章保留，舊制徽章另存收藏；目前沒有獨立雲端徽章資料表。

### 臨時遊戲測試

在頁面空白處連續輸入三個半形句點 `...` 可開啟測試選單；每次間隔須小於 1.5 秒。選單提供六款測驗、各遊戲現行訓練級別，以及帽子遊戲第 1～5 關。

測試使用虛構兒童及記憶體資料，不保存正式進度、結果、獎勵或雲端同步。可透過 `ENABLE_TEMPORARY_GAME_TESTING` 關閉入口。級別清單依目前 [catalog.js](../src/temporaryGameTesting/catalog.js) 及協定產生，ARI 已為五級。

## 9. 執行、驗證與部署

### 本機執行

```powershell
npm ci --legacy-peer-deps --no-audit --no-fund
npm start
```

需要 AI 或寄信功能時，完成後端與 Supabase 設定，再於另一個終端執行：

```powershell
npm run server
```

### 可用驗證指令

| 指令 | 用途 |
| --- | --- |
| `npm run check:assets` | 檢查資產引用 |
| `npm test -- --watchAll=false` | 前端 Jest 測試 |
| `npm run test:api` | API 安全及問答寄信測試 |
| `npm run test:rag` | RAG 情境與評估器測試 |
| `npm run eval:rag` | 產生 50 個情境的離線 JSON／CSV 報告 |
| `npm run build` | 正式建置 |
| `npm run check:deploy` | 檢查建置容量、單檔大小及禁止內容 |
| `npm run check` | 資產、Jest、建置及部署檢查；API／RAG 測試需另外執行 |

需要測試真實模型時可執行 `npm run eval:rag -- --mode=model`；真實檢索另以 `node scripts/test-rag-search.mjs` 核對。

### 部署範圍

GitHub Actions 使用 Node 20 建置靜態前端並發布 GitHub Pages，前端部署不包含 Express API、Supabase schema 或知識庫。現行部署檢查預設總容量上限為 230 MiB、單檔為 24 MiB。

完整 AI 與寄信服務需另有後端執行環境，並讓前端同源的 `/api/clinical-assistant`、`/api/assistant-email` 正確轉送至後端。GitHub Pages 本身不執行 Node API。

### 本次整理的確認範圍

本次為文件整理，核對原始碼、協定、環境變數範例、指令與本地連結。未重新執行測試、建置、真實模型評估、資料庫驗證或實際寄信；既有文件內的歷史測試數字不作為目前版本通過證明。
