# RAG 回覆的 50 種模擬情境

此評估套件使用 50 個固定情境，每題包含問題、虛構個案資料、合成知識段落、預期行為與人工核對重點。情境定義見 [scenarios.mjs](../scripts/rag/scenarios.mjs)，可直接新增或修改。套件不使用真實兒童資料，也不寫入資料庫。

## 執行方式

```powershell
# 不連外、不用金鑰；執行 50 個流程情境並輸出報告
npm run eval:rag

# 驗證 50 個情境及評估器本身的負面案例
npm run test:rag

# 使用 .env.rag 的 OPENAI_API_KEY 與 OPENAI_MODEL 產生真實回答
npm run eval:rag -- --mode=model

# 先挑選指定情境，或指定輸出目錄
npm run eval:rag -- --mode=model --case=RAG-31 --case=RAG-37
npm run eval:rag -- --out=artifacts/rag-evaluation-review
```

`model` 模式會呼叫真實模型並產生 API 費用。每題最多 1800 output tokens，循序執行、不自動重試；50 題中 48 題會嘗試產生回答，2 題驗證輸入拒絕。API 逾時為 120 秒。請先用少量情境核對設定；大量執行的總時間取決於模型。

兩種模式都透過正式臨床助手 handler、資料清理、文件去重／門檻處理與提示組裝；只在程式內注入測試用依賴，HTTP 請求不能指定依賴或切換模式。

| 模式 | 知識段落 | 回答 | 能確認的範圍 |
| --- | --- | --- | --- |
| `offline`（預設） | 合成固定段落 | 回覆替身 | 輸入驗證、提示組裝、缺值、來源處理、故障降級與欄位清理 |
| `model` | 合成固定段落 | 真實模型生成 | 上述流程，加上回覆關鍵內容、引用編號與注入標記的自動初查，並保留人工審查 |

離線 50/50 通過只代表流程檢查通過，不能當成 50 個真實回答正確。`model` 模式也沒有測試 Supabase 向量檢索的命中品質、HTTP 驗證、權限或速率限制；真實檢索仍需另外執行 `node scripts/test-rag-search.mjs` 並核對來源。合成段落不是文獻證據，報告不得當作臨床研究結論。

## 報告與判讀

每次執行在 `artifacts/rag-evaluation/` 產生帶時間戳記的 JSON 與可供 Excel 開啟的 UTF-8 BOM CSV。此目錄已被 Git 忽略。每完成一題就更新檔案；JSON 的 `complete`、`planned` 與 `summary.total` 可辨識執行中斷或部分情境。

- JSON：套件版本、模式、每題輸入雜湊、實際傳給模型的清理後證據、模型名稱、response ID、回答、引用、耗時、自動檢查與人工核對重點。
- CSV：每題問題／回答、自動檢查結果、失敗項目與人工審查狀態，可逐題填寫外部審查紀錄。
- `answerChecks: not_run`：未檢查真實模型回答；`heuristics_only`：只做關鍵內容、引用與注入標記檢查。
- `humanReview: pending`：真實模型案例仍需人工核對；自動通過不會改成「審查通過」。
- 任一自動檢查失敗，指令以非零狀態結束。API 錯誤或空回答會判為失敗，並保留其他情境的報告。

引用編號存在，只能證明該編號有對應來源，不能證明來源支持那句話；關鍵字命中也不能證明語意正確。人工需依各題 `reviewCriteria` 核對資料忠實性、引用支持程度、限制、注入抵抗、繁體中文與受眾適合度。診斷、用藥與個資案例應逐題核對，不以關鍵字檢查取代專業審查。

若要量化真實檢索效能，需另外建立經審核的實際知識庫題目及標準來源清單，記錄 retrieval recall／precision；本套件不會以合成資料計算這些指標。
